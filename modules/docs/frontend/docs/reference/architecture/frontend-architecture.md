# Frontend Architecture

The Compozerr template frontend is a React application built with Vite, using TanStack Router for routing and OpenAPI Qraft for type-safe API calls.

## TanStack Router

Routes are file-based. Files in `frontend/src/routes/` map directly to URL paths.

### Naming conventions

| File name | Purpose | URL |
|-----------|---------|-----|
| `index.tsx` | Index route for a directory | `/` or parent path |
| `about.tsx` | Static route | `/about` |
| `_layout.tsx` | Layout wrapper (no URL segment) | -- |
| `$id.tsx` | Dynamic parameter | `/:id` |
| `posts/index.tsx` | Nested index | `/posts` |
| `posts/$postId.tsx` | Nested dynamic | `/posts/:postId` |

### Example route

```tsx
// frontend/src/routes/dashboard/index.tsx
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/dashboard/")({
  component: DashboardPage,
});

function DashboardPage() {
  return <div>Dashboard</div>;
}
```

### Route tree generation

The route tree is auto-generated in `frontend/src/routeTree.gen.ts`. Do not edit this file -- it is regenerated whenever route files change during development.

If routes seem out of sync, delete `frontend/src/routeTree.gen.ts` and restart the dev server.

## OpenAPI Qraft

OpenAPI Qraft generates a type-safe API client from the backend's Swagger specification. The generated types live in `frontend/src/generated/`.

### Regenerating the API client

When the backend API changes, regenerate the client with the backend running on port 5000:

```bash
cd frontend && npx openapi-qraft \
  --plugin tanstack-query-react \
  --plugin openapi-typescript \
  http://localhost:5000/swagger/v1/swagger.json \
  --clean \
  -o src/generated \
  --export-type \
  --properties-required-by-default \
  --default-non-nullable
```

Do not manually edit files in `frontend/src/generated/`.

### Using the API client

The API client is configured in `frontend/src/api-client.ts` and provides React Query hooks for every endpoint.

**Queries** -- fetch data with automatic caching and refetching:

```typescript
import { api } from "./api-client";

function UserProfile() {
  const { data, isLoading, error } = api.v1.getAuthMe.useQuery();

  if (isLoading) return <div>Loading...</div>;
  if (error) return <div>Error: {error.message}</div>;

  return <div>Hello, {data.email}</div>;
}
```

**Mutations** -- create, update, or delete data:

```typescript
import { api } from "./api-client";

function LoginForm() {
  const { mutate, isPending } = api.v1.postLogin.useMutation();

  const handleSubmit = (email: string, password: string) => {
    mutate({ body: { email, password } });
  };

  return (
    <button onClick={() => handleSubmit("user@example.com", "password")} disabled={isPending}>
      {isPending ? "Signing in..." : "Sign in"}
    </button>
  );
}
```

## Module route integration

Modules contribute frontend routes through their `compozerr.json` configuration:

```json
{
  "frontend": {
    "routesDir": "frontend/src/routes"
  }
}
```

The file `frontend/virtual-route-config.ts` discovers module routes and merges them into the main route tree. Module routes work identically to routes in the main `frontend/src/routes/` directory -- same naming conventions, same file format.

This means a module can add pages to your app without modifying any existing code.
